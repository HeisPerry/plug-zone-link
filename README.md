# PlugZone Marketplace

Lovable Prompt: P2P Marketplace Platform

Copy Everything Below This Line and Send to Lovable

Build a full-stack peer-to-peer marketplace platform called PlugZone using React, TypeScript, Tailwind CSS, and Supabase. This is a platform where users can post product/service ads, receive orders, communicate via direct messaging, build social connections through friend requests, earn rewards through daily login streaks, and purchase data/airtime bundles. Every user gets a unique affiliate link for referral tracking.

CRITICAL DESIGN RULES --- READ BEFORE ANYTHING ELSE

Do NOT use any of the following patterns. The design must look like it was built by a human designer, not generated by AI:

Color restrictions:

No purple-to-blue gradient backgrounds anywhere in the app

No gradient buttons

No box-shadow on every element. Use 1px solid borders instead of shadows for card separation

No alternating gray/white section backgrounds

Do not use more than 3 colors total across the entire UI

Use this color system instead:

Base: white backgrounds with off-black text (#1A1A1A)

One accent color only: a muted teal (#0D9488) for primary actions, active states, and links

Neutral border color: #E5E5E5

Subtle background for secondary sections: #FAFAFA (use sparingly, not alternating)

Error: #DC2626. Success: #16A34A. Warning: #D97706. These appear only when contextually needed.

Typography restrictions:

Do NOT use Inter, Roboto, or Open Sans

Use Plus Jakarta Sans for headings (weight 700, letter-spacing -0.02em, line-height 1.15)

Use DM Sans for body text (weight 400/500, line-height 1.7)

Hero titles must be dramatically larger than subheadings (48px+ on desktop, 32px on mobile)

Body text: 15px-16px. Do not make everything 14px.

Layout restrictions:

No 3-column identical card grids repeated across multiple sections

No "heading then description then 3 cards" pattern repeated

Do not center-align everything. Left-align is the default. Center only for hero sections or very short standalone headings.

Mix layout types: single column content areas, two-column splits, horizontal scrolling card rows, and list-based layouts

Vary spacing between sections. Important sections get more vertical padding. Related sections sit closer together.

Copy and microcopy restrictions:

No vague phrases: "Unlock your potential", "Seamless experience", "Empower your workflow", "Get started today" are all banned

Every button must say exactly what it does: "Post an Ad", "Send Message", "Add Friend", "Check In", "Buy 1GB Data"

Section headings must be specific: "Your Active Ads" not "Dashboard". "Messages" not "Communication Hub". "Today's Check-In" not "Rewards Center".

Subtitles: one sentence maximum. If it needs more than one sentence, it belongs in body text below, not in the subtitle.

Icon and image restrictions:

No emoji used as icons anywhere in the entire application

Use Lucide React icons exclusively for all iconography

No AI-generated illustrations

No gradient placeholder boxes

No stock photos. If there is no real image for something, design the layout without an image. Do not fake it.

UX and interaction restrictions:

No scroll-reveal opacity animations

No sections with 50+ visible items. Show 6-8 items with a "Show more" or pagination control.

All tap targets must be minimum 44x44px on mobile

Maximum 2 call-to-action buttons per section (one primary, one secondary)

Vary the visual design of components between sections. Not every section should look like a card grid.

AUTHENTICATION SYSTEM

Sign Up Page:

Full page layout, not a modal

Left side: a brief value proposition in large text (left-aligned) with a subtle pattern or solid color background (#FAFAFA)

Right side: the sign up form

Fields: Display Name, Username (validated for uniqueness in real-time with a debounced check against Supabase, showing a small green checkmark or red X inline), Email, Password, Confirm Password, optional Referral Code field (pre-filled from URL query param if the user arrived via an affiliate link)

Password requirements displayed as a checklist that checks off in real-time: minimum 8 characters, one uppercase, one lowercase, one number, one special character

Submit button: "Create Account"

Link at bottom: "Already have an account? Sign in"

On successful signup, send email verification via Supabase Auth, redirect to a "Check your email" page

Login Page:

Same split layout as sign up for visual consistency

Fields: Email, Password

"Forgot password?" link below password field that triggers Supabase password reset email

Submit button: "Sign In"

Link at bottom: "New here? Create an account"

On successful login, redirect to dashboard and trigger daily streak logic

Security:

Use Supabase Auth with email/password provider

Implement Row Level Security (RLS) on all Supabase tables

All API calls authenticated via Supabase session tokens

Rate limit login attempts on the frontend (disable button for 30 seconds after 5 failed attempts, show countdown)

Store passwords via Supabase (bcrypt hashed automatically)

Session timeout after 30 minutes of inactivity with a warning modal at 25 minutes

CSRF protection via Supabase's built-in token handling

DATABASE SCHEMA (Supabase / PostgreSQL)

Create the following tables with RLS enabled on all of them:

profiles:

id (UUID, references auth.users, primary key)

username (TEXT, unique, not null, indexed, lowercase enforced via trigger)

display_name (TEXT, not null)

avatar_url (TEXT, nullable)

bio (TEXT, nullable, max 300 characters)

affiliate_code (TEXT, unique, not null, auto-generated on signup as a random 8-character alphanumeric string)

referred_by (UUID, nullable, references profiles.id)

total_referrals (INTEGER, default 0)

current_streak (INTEGER, default 0)

longest_streak (INTEGER, default 0)

last_check_in (DATE, nullable)

created_at (TIMESTAMPTZ, default now())

updated_at (TIMESTAMPTZ, default now())

ads:

id (UUID, primary key, default gen_random_uuid())

seller_id (UUID, references profiles.id, not null)

title (TEXT, not null, max 120 characters)

description (TEXT, not null, max 2000 characters)

price (NUMERIC, not null)

currency (TEXT, default 'NGN')

category (TEXT, not null)

images (TEXT[], array of image URLs, max 5)

status (TEXT, default 'active', enum: active/paused/sold/deleted)

location (TEXT, nullable)

created_at (TIMESTAMPTZ, default now())

updated_at (TIMESTAMPTZ, default now())

orders:

id (UUID, primary key, default gen_random_uuid())

ad_id (UUID, references ads.id, not null)

buyer_id (UUID, references profiles.id, not null)

seller_id (UUID, references profiles.id, not null)

status (TEXT, default 'pending', enum: pending/accepted/completed/cancelled/disputed)

quantity (INTEGER, default 1)

total_price (NUMERIC, not null)

notes (TEXT, nullable)

created_at (TIMESTAMPTZ, default now())

updated_at (TIMESTAMPTZ, default now())

messages:

id (UUID, primary key, default gen_random_uuid())

conversation_id (UUID, not null, indexed)

sender_id (UUID, references profiles.id, not null)

receiver_id (UUID, references profiles.id, not null)

content (TEXT, not null, max 2000 characters)

read (BOOLEAN, default false)

created_at (TIMESTAMPTZ, default now())

conversations:

id (UUID, primary key, default gen_random_uuid())

participant_one (UUID, references profiles.id, not null)

participant_two (UUID, references profiles.id, not null)

last_message_at (TIMESTAMPTZ, default now())

created_at (TIMESTAMPTZ, default now())

UNIQUE constraint on (participant_one, participant_two) with participant_one < participant_two enforced

friend_requests:

id (UUID, primary key, default gen_random_uuid())

sender_id (UUID, references profiles.id, not null)

receiver_id (UUID, references profiles.id, not null)

status (TEXT, default 'pending', enum: pending/accepted/rejected)

created_at (TIMESTAMPTZ, default now())

UNIQUE constraint on (sender_id, receiver_id)

friendships:

id (UUID, primary key, default gen_random_uuid())

user_one (UUID, references profiles.id, not null)

user_two (UUID, references profiles.id, not null)

created_at (TIMESTAMPTZ, default now())

UNIQUE constraint on (user_one, user_two) with user_one < user_two enforced

daily_checkins:

id (UUID, primary key, default gen_random_uuid())

user_id (UUID, references profiles.id, not null)

check_in_date (DATE, not null)

streak_count (INTEGER, not null)

created_at (TIMESTAMPTZ, default now())

UNIQUE constraint on (user_id, check_in_date)

affiliate_clicks:

id (UUID, primary key, default gen_random_uuid())

affiliate_user_id (UUID, references profiles.id, not null)

clicked_at (TIMESTAMPTZ, default now())

ip_hash (TEXT, nullable, for deduplication)

converted (BOOLEAN, default false)

data_airtime_orders:

id (UUID, primary key, default gen_random_uuid())

user_id (UUID, references profiles.id, not null)

type (TEXT, not null, enum: data/airtime)

provider (TEXT, not null, enum: MTN/Airtel/Glo/9mobile)

phone_number (TEXT, not null)

amount (NUMERIC, not null)

data_plan (TEXT, nullable, e.g. "1GB", "2GB", "5GB")

status (TEXT, default 'pending', enum: pending/processing/completed/failed)

reference (TEXT, unique, not null)

created_at (TIMESTAMPTZ, default now())

PAGE STRUCTURE AND FEATURES

1. Landing Page (unauthenticated users only)

Layout: single scrolling page, no sidebar.

Hero section: large left-aligned heading "Buy and sell directly, no middleman." with one line of supporting text below it and a single "Create Account" button (teal, solid, no gradient). Right side of the hero: a clean illustration-free stat block showing live counts (total users, total ads, transactions completed) pulled from Supabase using a public read-only view.

"How It Works" section: horizontal 3-step flow (not a card grid). Step 1: "Post your ad with photos and pricing." Step 2: "Buyers find you and place orders." Step 3: "Chat, finalize, and complete the deal." Each step is a numbered item in a horizontal line with a connecting line between them. No icons, no cards, just numbered text with a subtle horizontal connector line.

Social proof section: a single row of 4-5 real aggregate stats (not testimonials), such as "12,400+ ads posted", "3,200+ completed orders", etc. Styled as a single horizontal strip with a light background.

Footer: links to Sign Up, Login, Terms, Privacy. No social media icons unless there are real accounts to link to.

2. Dashboard (authenticated)

Layout: sidebar navigation on the left (collapsible on mobile into a bottom tab bar), content area on the right.

Sidebar links: Dashboard, My Ads, Orders, Messages, Friends, Check-In, Buy Data/Airtime, Profile, Settings, Sign Out.

Dashboard content:

Top: greeting "Welcome back, [display_name]" with today's date

Row of 4 stat cards (horizontal, not grid): Active Ads count, Pending Orders count, Unread Messages count, Current Streak (days)

Below stats: "Recent Orders" list showing the 5 most recent orders with status badges (colored text, not colored backgrounds). Each row: ad title, buyer/seller name, status, date. "View all orders" link at bottom.

Below that: "Recent Messages" showing the 3 most recent conversations with the last message preview, other person's name, and timestamp. "View all messages" link.

3. My Ads Page

Top: "My Ads" heading with a "Post New Ad" button (teal, solid) aligned to the right

Filter bar: dropdown for status (All, Active, Paused, Sold) and a search input

Ads displayed as a vertical list (not a card grid), each row showing: first image thumbnail (small, square, left-aligned), title, price, category badge, status badge, date posted, and action buttons (Edit, Pause/Resume, Delete)

Pagination at the bottom: show 10 ads per page

Post/Edit Ad Form (modal or separate page):

Title input (max 120 chars, character counter shown)

Description textarea (max 2000 chars, character counter shown)

Price input with currency selector (NGN default)

Category dropdown: Electronics, Fashion, Services, Vehicles, Property, Food, Health, Education, Other

Image upload: drag-and-drop zone, max 5 images, max 2MB each, preview thumbnails shown after upload. Store in Supabase Storage.

Location input (free text)

Submit button: "Post Ad" or "Update Ad"

4. Ad Detail Page (public)

Accessible by URL: /ad/[ad-id]

Left: image gallery (if multiple images, horizontal scroll with thumbnail strip below)

Right: title, price (large, bold), category badge, seller username (clickable, links to /user/[username]), location, posted date

Description below in full

Two action buttons: "Place Order" (teal, primary) and "Message Seller" (outlined, secondary)

If the viewer is the ad owner, show "Edit Ad" and "Delete Ad" buttons instead

5. Orders Page

Two tabs: "Buying" and "Selling"

Each tab shows a list of orders with: ad title (clickable), other party's username, quantity, total price, status badge, date

Clicking an order expands inline to show full details and action buttons:

Buyer can: Cancel (if pending)

Seller can: Accept, Complete, Cancel (depending on current status)

Status flow: pending -> accepted -> completed. Either party can cancel before completion. Disputed status available via a "Report Issue" link.

6. Messages Page

Left panel: conversation list sorted by last_message_at descending. Each item shows the other user's display name, avatar placeholder (initials in a colored circle, color derived from username hash), last message preview (truncated to 60 chars), timestamp, and unread indicator (small teal dot).

Right panel: active conversation thread. Messages displayed in a chat-style layout: sender's messages right-aligned (light teal background), receiver's messages left-aligned (light gray background). Timestamps shown on each message. Input bar at the bottom with a text input and "Send" button.

Real-time messaging via Supabase Realtime subscriptions on the messages table.

On mobile: conversation list is full-width, tapping a conversation navigates to the thread view with a back button.

Starting a new conversation: if a user clicks "Message Seller" from an ad detail page or "Message" from a user profile, check if a conversation already exists between the two users. If yes, open it. If no, create one.

7. Friends Page

Three tabs: "Friends", "Requests", "Find People"

Friends tab:

List of accepted friends: avatar (initials circle), display name, username, "Message" button, "Remove" button

If no friends yet, show a simple text: "You haven't added any friends yet. Search for people to connect with."

Requests tab:

Incoming requests: other user's name, username, "Accept" and "Decline" buttons

Outgoing requests: other user's name, username, "Cancel Request" button

Separate the two groups with a simple text divider

Find People tab:

Search input at the top: "Search by username"

Debounced search (300ms) querying the profiles table by username (case-insensitive partial match using ilike)

Results displayed as a list: avatar, display name, username. Each result has a contextual button: "Add Friend" (if no relationship), "Pending" (if request already sent, disabled), "Friends" (if already friends, disabled), or "Accept" (if they sent you a request).

Show max 20 results.

8. User Profile Page (public)

URL: /user/[username]

Display name (large), username below it (smaller, gray)

Bio text

Member since date

Stats row: number of ads posted, number of completed orders, referral count

If viewing your own profile: "Edit Profile" button

If viewing another user's profile: "Add Friend" / "Friends" / "Pending" button, and "Send Message" button

Below: list of that user's active ads (same format as My Ads but read-only, showing only active ads)

9. Daily Check-In Page

Heading: "Daily Check-In"

Large current streak number displayed prominently (e.g., "7 days" in large text) with "Longest streak: 14 days" below it in smaller text

A calendar-style grid showing the current month with checked-in days highlighted (filled teal circles) and today either highlighted as "Check In" if not done, or filled if done

"Check In" button (large, teal, centered). If already checked in today, the button is disabled and reads "Checked In Today" with a checkmark icon.

Check-in logic: on button click, insert a row into daily_checkins with today's date. Update profiles.current_streak: if last_check_in was yesterday, increment current_streak by 1. If last_check_in was before yesterday, reset to 1. Update longest_streak if current_streak exceeds it. Update last_check_in to today.

Below the calendar: a simple milestone tracker. Text-based list: "3-day streak", "7-day streak", "14-day streak", "30-day streak", "60-day streak", "100-day streak" with a checkmark or empty circle next to each based on longest_streak.

10. Affiliate Section

Located in Profile > Settings, or as a tab within the Profile page

Heading: "Your Referral Link"

Display the user's unique affiliate URL: [YOUR_DOMAIN]/join?ref=[affiliate_code]

"Copy Link" button that copies to clipboard and shows a brief "Copied" confirmation

Stats below: Total clicks, Total signups from your link, Conversion rate (clicks to signups percentage)

Data pulled from affiliate_clicks table filtered by the user's affiliate_code

When a new user visits the site via an affiliate link, log a row in affiliate_clicks. If that visitor signs up, mark that row as converted and set profiles.referred_by to the affiliate user's id. Increment the affiliate user's total_referrals count.

11. Buy Data and Airtime Page

Two tabs: "Buy Data" and "Buy Airtime"

Buy Data tab:

Step 1: Select network provider. Four large selectable cards in a row: MTN (yellow accent), Airtel (red accent), Glo (green accent), 9mobile (dark green accent). Each card just has the provider name and a radio-style selected state (teal border when selected).

Step 2: Enter phone number. Input field with basic validation (11 digits for Nigerian numbers). A "Use my number" autofill option if the user has a saved phone number in their profile.

Step 3: Select data plan. A vertical list of plans for the selected provider. Each row: data amount (e.g., "1GB"), validity period (e.g., "30 days"), price. Selectable with a radio-style indicator.

Step 4: Review and confirm. Summary showing provider, phone number, plan, and price. "Pay [amount]" button.

After payment: show a confirmation screen with the order reference number and status. Save to data_airtime_orders table.

NOTE: For now, the payment integration is a placeholder. Create the full UI flow and save orders to the database with "pending" status. Add a comment in the code where the actual payment API call would go (e.g., Paystack or Flutterwave integration point).

Buy Airtime tab:

Same provider selection as data tab

Phone number input

Amount input (free-form numeric input, minimum 50, maximum 50000)

Review and confirm step

Same payment placeholder logic

12. Settings Page

Profile section: edit display name, bio, avatar (upload to Supabase Storage)

Account section: change email, change password (both via Supabase Auth)

Notifications: toggle switches for email notifications on new messages, new orders, friend requests (store preferences in a user_settings table or as a JSONB column on profiles)

Saved phone number: input to save a default phone number for data/airtime purchases

Delete account: red "Delete Account" button with a confirmation modal that requires typing the username to confirm

GLOBAL COMPONENTS

Navigation (authenticated):

Desktop: fixed left sidebar, 240px wide, white background, 1px right border (#E5E5E5). Logo/app name at top. Navigation links below with Lucide icons (small, 18px) next to text labels. Active link: teal text + light teal background. Unread message count badge (small teal circle with number) next to Messages link.

Mobile: fixed bottom tab bar with 5 key icons (Dashboard, Ads, Messages, Check-In, Menu). Menu opens a slide-out drawer with full navigation. No hamburger animation. Simple slide transition.

Notifications (in-app):

Toast notifications for actions: "Ad posted", "Order accepted", "Message sent", "Friend request sent", "Checked in - 5 day streak!"

Use a simple toast system: appears top-right, white background, 1px border, auto-dismiss after 4 seconds. No slide-in animation, just appear/disappear.

Empty States:

Every list page must have an empty state with specific, helpful text. Not "Nothing here" but "You haven't posted any ads yet. Post your first ad to start selling." with a relevant action button.

Loading States:

Use skeleton loaders (simple gray rectangles with a subtle pulse animation) for content areas while data loads. Not spinners.

Error States:

Inline error messages below form fields (red text, small). Not alert boxes.

Page-level errors: a simple centered message with a "Try again" button.

TECHNICAL REQUIREMENTS

React 18+ with TypeScript

Tailwind CSS for all styling (no CSS modules, no styled-components)

Supabase for auth, database, storage, and realtime

React Router for navigation

React Query (TanStack Query) for data fetching and caching

Zustand or React Context for minimal global state (auth user, theme)
